# 出荷ピッキング照合ツール

「本日出荷リスト」（Googleスプレッドシート。PC側の同期で30分ごとに更新）をもとに、
出荷指示書 → 商品 → 発送ラベルの順にバーコードで照合し、梱包完了を「記録」シートに書き込む。

| ファイル | 内容 |
|---|---|
| `index.html` | 照合ツール（スマートフォンで使う） |
| `print.html` | 出荷指示書・ピッキングリストの印刷ページ（作業所のPC・プリンターで使う） |
| `picklist.js` | ピッキングリストの集計（画面・通信なし。print.html から使う） |
| `config.js` | Apps Script のURL・カメラ・追跡番号の形式・梱包資材の判定条件 |
| `common.js` | 共通処理（接続キー・Apps Scriptの呼び出し・梱包資材の判定） |
| `gas/Code.gs` | Apps Script（作業記録スプレッドシートに紐づくスクリプト）のコード。更新手順は `gas/DEPLOY.md` |
| `dev/mock-gas-server.mjs` | 試験用サーバー（本物の Code.gs を偽のシートで動かす。本番には接続しない） |

## 接続キー
Apps Script のトークンは公開リポジトリに載せず、各端末でブラウザに保存する。設定方法は「手入力」と「QRコード」の2つ。
- **QRコード**: `https://tomysshop0513.github.io/picking-scan-tool/#key=接続キー` をQRコードにし、スマホの標準カメラで読むと
  ツールが開いてキーが保存される（「接続キーを保存しました」と表示。すでにキーがあっても上書きする）。
  読んだらすぐ URL から `#` 以降を消す（アドレスバー・履歴に残さない）。印刷ページ（print.html）でも同じ
  - QRコードはPCで `python local/make_key_qr.py` で作る（キーは実行時に非表示で入力。外部のQR生成サイトは使わない）。
    `local/` は .gitignore 対象で、スクリプトもPNGもコミットしない。必要なもの: `pip install "qrcode[pil]"`
  - QRコードの画像・印刷物は接続キーそのもの。配布が済んだら削除・破棄し、漏れたらトークンを変更する（gas/DEPLOY.md）
- `?key=`（クエリ）では設定できない: サーバーに送られ、外部サービス経由で開いたときに第三者のアクセスログに残るため。
  `#key=`（ハッシュ）はブラウザからサーバーへ送られない
- 初回は入力欄が表示される。変更はホーム画面（印刷ページはツールバー）の「接続キーを変更」から
- キーが違うと「接続キーが正しくありません」と表示され、保存したキーは消える（入れ直せる）

## 担当者
ホーム画面の担当者ボタンは、スプレッドシート（本日出荷リストと同じファイル）の「担当者」シートから読み込む。
コード・config.js には担当者名を書かない。
- 「担当者」シート: A1=見出し、A2から下に1行1名。空白行は無視、前後の空白は除き、重複は1つにする（シートの並び順で表示）
- ホーム画面を開いたとき・「更新」を押したときに、注文一覧と一緒に取得する（Apps Script の `action=workers`）
- 取得できたらこの端末に保存する（localStorage `pickingToolWorkers`）。通信できないときは保存済みのリストを表示し、
  保存も無ければ「担当者を取得できません」と「再取得」ボタンを出す
- シートが無い・名前が0件のときは、その理由と「再取得」ボタンを出す（古い保存済みのリストは使わない）
- 選択中の担当者がリストから消えたら、選択を解除する。作業記録（「記録」シートG列）には選んだ名前をそのまま書く

## 試験用サーバー（本番に接続せずに確認する）
```
node dev/mock-gas-server.mjs
```
- 照合ツール: http://localhost:8787/ （接続キー: `test-key`）
- 状況の切り替え: http://localhost:8787/__mock （「担当者」シートが 2名以上 / 1名 / 空 / シート無し / 通信できない）
- 本物の `gas/Code.gs` を、メモリ上の偽のシートの上で動かす。配信する config.js の GAS_URL だけを試験用サーバーに差し替える。
  作業記録も偽のシートに書く（切り替え画面で確認できる。サーバーを止めると消える）
- PCのブラウザ専用（127.0.0.1 のみで待ち受け）。カメラを使う確認はできない
- 試験データ: `MOCK_FIXTURE=データ.json node dev/mock-gas-server.mjs` で、偽のシートを差し替え・追加できる
  （`{"本日出荷リスト": [[見出し…], [値…]], "商品マスタ": [...]}` の形。ピッキングリストの確認などに使う）

## 照合ツールの流れ
1. **STEP1 出荷指示書**: 注文番号のバーコード(CODE128)を読むと、その時点の最新状態をApps Scriptに問い合わせる
   - 未処理 → STEP2 / 完了（「記録」シートに記録済みを含む）→「梱包済みです」で停止
   - 対象外 →「この注文は梱包しないでください」で停止 / リストに無い → NG
   - 警告（JAN未登録など）がある →「この注文は梱包できません。担当者に連絡してください」で停止
   - 「印刷記録」に無い注文 →「この指示書は印刷記録がありません」と注意（「このまま進む」でSTEP2へ。記録漏れの検知用）
2. **STEP2 商品**: JAN（商品マスタB列。カンマ区切りの複数JANはどれでも可。Code39・FNSKUも可）を数量分スキャン
3. **STEP3 発送ラベル**: 「姓 様 / 都道府県」を大きく表示 → ラベルの追跡番号をスキャン
   - 形式チェック（`config.js` の TRACKING。前後の英字・空白・ハイフンを除いてから判定）
   - 別の注文で記録済みの追跡番号は NG（サーバー側でも重複を確認）
4. 完了時に「記録」シートへ書き込み、成功を確認してから完了画面を出す（失敗時は再送ボタン）

## 読み取りテスト
ホーム画面の下の「読み取りテスト」。バーコードを読むと、読んだ生の値・バーコード形式・文字数と、
追跡番号の形式（config.js の TRACKING）に合うかを表示する（記録はしない）。
クリックポストのラベルを読み、追跡番号の桁数・バーコード形式を確定して `config.js` の TRACKING に反映する。
下の枠に、切り分け用のカメラ情報を表示する（実際の解像度・フォーカス・ズーム(1x/光学2x/デジタル2x)と読み取り範囲・読み取り処理が回っているか「検出中 N回/秒」・ZXingの版）。

## バーコード読み取り（ZXing）
- ZXing `@zxing/library` 0.23.0（CDN）。**NW-7(Codabar) は 0.20.0 以降でないと読めない**（0.19.1 は未実装で、形式に指定しても無視される）。
  版を変えるときは `index.html` の `<script src>` と `ZXING_VERSION` を合わせる
- カメラは `config.js` の CAMERA（既定 ideal 1920×1080）を要求する。端末が対応しない場合は自動で下がる。
  連続オートフォーカスは対応端末（主にAndroid）のみ有効にする
- 読み取りは約200msごと（1秒に約5回）に、映像を canvas に写して ZXing でデコードする
- カメラ枠の右上の「ズーム 1x/2x」で切り替える（選択は端末に記憶。既定は 2x）。2x のときは
  - カメラ自体のズーム（`track.getCapabilities().zoom`）が2倍まで使える端末ではそれを使う（光学2x）
  - 使えない端末では、映像の中央50%（縦横とも半分）だけを切り抜いて読み取り、画面も同じく2倍に拡大表示する（デジタル2x）。枠は16:7のまま
- TRY_HARDER は既定で無効（1920×1080では、読めないフレームの処理が約9倍重くなるため）。`config.js` の CAMERA.tryHarder で切り替え

## 出荷指示書（print.html）
- 初期表示は「まだ印刷していない未処理の注文」（注文日時の古い順）で、全件選択済み。「印刷済みも表示」で印刷済みも出せる
- A4 1枚に6件（2列×3段、1枠 約105×99mm、枠の間に薄い切り取り線）。右上に印刷日時と通し番号（例: 3/12）
  - 印刷は Chrome で 用紙A4・余白「なし」（または最小）にする
  - 注文番号バーコード(CODE128)は枠の幅いっぱい(約95mm)。楽天の26文字の注文番号で1モジュール約0.37mm
  - 商品が多く1枠に収まらない注文は、同じ列の縦2枠を使う。それでも収まらなければ1ページを使う（文字は縮めない）。
    1ページにも収まらない場合は次のページへ続け、続きのページにも注文番号と表の見出しを出す
- 警告がある注文は赤字で表示し、選択できない。印刷済みを含むときは「再印刷です」と確認する
- 印刷後「印刷できましたか？」でOKを押すと、シート「印刷記録」（A=注文ID / B=印刷日時 / C=端末）に追記する（キャンセルなら記録しない）。
  「印刷済み」は印刷記録に注文IDがあるかで判定し、複数回印刷した場合は最新の日時を表示する
- 梱包資材は商品マスタD〜F列（寸法cm）が登録済みの場合のみ判定する

## ピッキングリスト（print.html の「ピッキングリスト印刷」）
注文ごとの梱包の前に、その日の出荷分を棚からまとめて取り出すための総量リスト。A4縦で印刷する（Chrome、用紙A4。余白はページ側で設定済み）。
- 対象: 本日出荷リストの「未処理」の注文すべて（一覧の選択・印刷済みかには関係しない）。ボタンを押した時点の最新の
  本日出荷リストと商品マスタを読む（Apps Script の `action=list` と `action=master`）
- 数える商品: 商品マスタ「自社出荷(毛呂山)」にチェックがある商品だけ（混在注文はチェックありの分だけ）
  - 本日出荷リストの商品はPC側の同期でセット展開・RSL出荷の除外が済んでいるが、印刷時にも商品マスタで確かめる
    （H列「セット構成」があれば単品に展開、チェックなしなら数えない）
  - 商品マスタに無い商品は数えて「商品マスタ未登録」の印をつける（取り出し漏れを防ぐ）
  - 警告がある注文（伝票番号登録済み・要確認 など）も数え、その商品の行に「要確認」の印。最後に要確認の注文番号と警告を出す
- まとめ方: 商品マスタB列の**先頭のJAN**が同じ商品は1行（例: 1225-001038 と 1225-001038-c）。商品名は短い方を出す
- 各行: □（取り出したらチェック）/ 棚番号 / 商品名とJAN / 合計数量（大きく太字）/ 対象注文数。最後に品目数と総点数。
  お届け先などの個人情報は載せない
- 棚番号: 商品マスタの見出し「棚番号」の列（J列。形式 `A-2-3` ＝ ラック-段-位置）。列は**見出し名**で探す（位置は使わない）
  - 先頭のJANが同じ行のどれか1つに入れればよい（-c 付きの行にも同じ棚番号を入れる必要はない）。違う棚番号が入っていると両方を出し「棚番号が複数」の印
  - 全角・小文字・長音記号「ー」などは `A-2-3` の形にそろえて扱う
- 並び順: 棚番号順（A-1-1, A-1-2 … A-5-3, A-10-1, B-1-1 …。数字は数値として比べる）。棚番号が空欄の商品は最後に「棚番号なし」として商品名順
- ピッキングリストは「印刷記録」に残さない（何度印刷してもよい）
