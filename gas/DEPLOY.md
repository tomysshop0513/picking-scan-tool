# Apps Script の更新手順（URLを変えずに新しいバージョンにする）

トークンはコードに書かず、**スクリプトプロパティ `SECRET_TOKEN`** に保存する。
コードを貼り替えてもトークンは消えない（プロパティはコードとは別に保存される）。

## 1. 今のトークンを控える（初回のみ）
1. 作業記録スプレッドシート → 拡張機能 → Apps Script を開く
2. 今のコードを全部コピーしてメモ帳などに保存しておく（戻すとき用）
3. 今のコードの `var SECRET_TOKEN = "...";` の `"..."` の中身（今のトークン）を控える

## 2. スクリプトプロパティにトークンを設定する（初回のみ）
1. Apps Script の左のメニュー「⚙ プロジェクトの設定」を開く
2. 一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
3. プロパティ: `SECRET_TOKEN` ／ 値: 1-3 で控えたトークン → 「スクリプト プロパティを保存」
   - 未設定のままだと、すべてのリクエストを拒否する（照合ツール・印刷ページが「接続キーが正しくありません」になる）

## 3. コードを貼り替える
1. エディタの `Code.gs` の中身を全部消し、このフォルダの `gas/Code.gs` の内容を貼り付ける
   （新しいコードにはトークンを書く場所は無い）
2. 保存（Ctrl+S）

## 4. デプロイ（URLを変えない）
1. 右上の「デプロイ」→「デプロイを管理」
2. 既存のデプロイを選び、鉛筆（編集）アイコン
3. バージョン:「新バージョン」、説明に「追跡番号・印刷記録・order/tracking 追加」など → 「デプロイ」
   - **「新しいデプロイ」は使わない**（URLが変わり、config.js の書き換えが必要になる）
4. 初回は「アクセスを承認」を求められることがある（自分のGoogleアカウントで承認）

## 5. 動作確認
- PCのブラウザで照合ツール（またはローカルの print.html）を開き、設定画面で接続キー（トークン）を入力 → 一覧が表示されればOK
- ※ ブラウザのアドレス欄に `?token=...` を付けてURLを直接開く確認はしない（閲覧履歴等にトークンが残るため）

## トークンを変更する手順
1. 新しいトークンを決める（推測されにくい長い文字列。例: パスワード生成で作った32文字程度の英数字）
2. Apps Script →「⚙ プロジェクトの設定」→ スクリプト プロパティ → `SECRET_TOKEN` の値を新しいトークンに書き換えて保存
   - 再デプロイは不要（プロパティは保存した時点で反映される）
3. 照合ツールを使う各端末・印刷するPCで、「接続キーを変更」から新しいトークンを入力する
   - 古いキーのままの端末は「接続キーが正しくありません」と表示され、保存していたキーが消えるので、入力欄から入れ直す

## 変更点（元のコードとの違い）
- トークン: コードへの直書き（SECRET_TOKEN 変数）を廃止し、スクリプトプロパティ `SECRET_TOKEN` から読む。未設定なら全リクエストを拒否
- doGet: `action=order`（注文1件の最新状態。「記録」シートも見て完了を判定）、`action=tracking`（追跡番号の使用済み確認）を追加。
  `list` / `order` の各注文に `warning`（G列）・`orderedAt`（H列 注文日時）・`printedAt`（「印刷記録」シートの最新の印刷日時）を追加。`test` はそのまま
- doPost:
  - トークン確認を追加（本文の `token`）
  - `action=printed`: 出荷指示書を印刷した注文を、新しいシート「印刷記録」（A=注文ID / B=印刷日時 / C=端末）に追記する。
    シートが無ければ自動で作る。再印刷は行を追加し、最新の日時を「印刷済み」として使う。LockService で排他
  - 作業記録: 「記録」シートのH列に「追跡番号」を追加（既存のA〜G列の並びは同じ）。
    同じ注文の二重記録・追跡番号の重複はロックの中で確認して拒否する

## 注意
- doPost にトークン確認を追加したため、**旧版の照合ツール（サンプルデータ版）からの記録は拒否される**。
  Apps Script の更新と、照合ツールの main への反映（GitHub Pages の公開）は同じタイミングで行う
- このスクリプトは「本日出荷リスト」に書き込まない（読むだけ）。本日出荷リストはPC側の同期（30分ごと）が行を並べ替えて書き直すため、
  行番号に依存して書くと、同期と重なったときに別の注文の行に書かれるおそれがある。印刷の記録は注文IDをキーに「印刷記録」へ追記する
- 「印刷記録」はPC側の同期から一切触らない（picking_orders のテストで確認している）。不要な古い行は手で削除してよい
