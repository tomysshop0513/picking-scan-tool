# Apps Script の更新手順（URLを変えずに新しいバージョンにする）

1. 作業記録スプレッドシート → 拡張機能 → Apps Script を開く
2. 念のため、今のコードを全部コピーしてメモ帳などに保存しておく（戻すとき用）
3. `Code.gs` の中身を全部消し、このフォルダの `gas/Code.gs` の内容を貼り付ける
4. 貼り付けたコードの `var SECRET_TOKEN = "";` の `""` の中に、**今まで使っていたトークンの値**を入れる
   （手順2で保存した元のコードの SECRET_TOKEN と同じ値）
   - 代わりに「プロジェクトの設定 → スクリプト プロパティ」に `SECRET_TOKEN` を追加しても良い（こちらが優先される）
   - どちらも空のままだと、すべてのリクエストを拒否する（照合ツールが使えなくなる）
5. 保存（Ctrl+S）
6. 右上の「デプロイ」→「デプロイを管理」→ 既存のデプロイの鉛筆（編集）アイコン
   → バージョン:「新バージョン」→ 説明に「追跡番号・order/tracking 追加」など → 「デプロイ」
   - 「新しいデプロイ」は使わないこと（URLが変わってしまう）
7. 動作確認: ブラウザで `{WebアプリURL}?token={トークン}&action=list` を開き、`{"orders":[...]}` が返ればOK

## 変更点（元のコードとの違い）
- doGet: `action=order`（注文1件の最新状態。「記録」シートも見て完了を判定）、`action=tracking`（追跡番号の使用済み確認）を追加。
  `list` の各注文に `warning`（本日出荷リストG列）を追加。`test` はそのまま
- doPost: トークン確認を追加（本文の `token`）。「記録」シートのH列に「追跡番号」を追加（既存のA〜G列の並びは同じ）。
  同じ注文の二重記録・追跡番号の重複はロックの中で確認して拒否する
- トークン: スクリプトプロパティ `SECRET_TOKEN` を優先。空なら全リクエストを拒否

## 注意
- doPost にトークン確認を追加したため、**旧版の照合ツール（サンプルデータ版）からの記録は拒否される**。
  Apps Script の更新と、照合ツールの main への反映（GitHub Pages の公開）は同じタイミングで行う
